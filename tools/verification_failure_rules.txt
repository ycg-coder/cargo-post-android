# §三十三 四类构建/验证失败的**唯一规则表**（F-2 第 7 步）
# 消费者：tools/classify_verification_failure.sh（判据 VF-*）、app/src/test/.../VerificationFailureTest.kt
# 格式：三列 TAB 分隔 —— MARKER <TAB> 字面量 <TAB> 出处
#
# 四条刻意的写法约束（每条都是被坑过或推理出来的，不是风格）：
#  1) 字面量只准 **纯文本子串**（分类器用 grep -aF，用例用 String.contains）：
#     一旦允许正则，bash 的 grep -E 与 JVM 的 Regex 语义就不再等价，同一份日志两侧可能分出不同结果。
#     用例 VF/`F-b` 逐行验"字面量里不含正则元字符"，把这条约束钉成机器闸。
#  2) 只准 **ASCII**：样例日志的编码不统一（worker 日志混有 GBK 字节与 EF BF BD 替换符；
#     编译错误日志里的家目录名是 E8 A2 81 三字节序列，不是 UTF-8 的 袁）。
#     非 ASCII 模式在这种混合编码上会安静地读 0，而"读 0"和"真的没有"长得一样。
#  3) **不用 `> Task :app:... FAILED` 这类任务失败行**当任何一类的判据：
#     四类失败都会带任务失败行（用例失败也带），拿它分类等于什么都不分。
#     反面证据在册：negative-control-tests-failed-not-a-build-failure.log 里有
#     `Task :app:testDebugUnitTest FAILED` 与 `BUILD FAILED`，四类字面量**一条都不命中** ⇒ 正确输出是 UNCLASSIFIED。
#  4) **不用 `List of devices attached`** 判设备不可用：那行在"接着一台设备"与"后面空着"两种输出里都在，
#     它只是表头不是缺席证据。用的是 adb 真报错 `no devices/emulators found`（本轮实测 rc=1）。
#

风险 1 · 未跑真机/模拟器。 本环境无 Android 模拟器与真机，因此以下未验证：界面实际渲染、扫码相机调用、 高德底图加载、GPS 定位链路、下拉刷新手势、通知栏提醒。 已验证的是编译级 + 免登录接口与高德 REST 的真实响应（见第七节）。 建议真机按此主链路走一遍：登录 → 首页闪屏 → 首页天气卡展开 → 商城下单 → 寄货（出二维码）→ 快递查件 → 司机发车 → 扫码装车 → 妥投 → 溯源看凭证。
风险 2 · 演示数据兜底会掩盖后端契约问题。 Android 端 Api.kt 在接口失败或返回空时回落 DemoData，页面只挂一个「演示数据」标签。 这在答辩演示时是优点（断网也能走完流程），但会让「字段真的对不上」和「后端没启动」看起来一样。 排查时先看 logcat 的 BUS_API tag。实测 product/list、notice/list、bus/lines 三个接口库中确无数据，所以演示必然走兜底路径。
风险 3 · 改密与登录时序依赖短信通道。 update-password 已按小程序改为 {password, code}（scene=3 短信验证码）。 若后端短信服务未配置，改密链路无法端到端验证——这属后端凭证问题，非客户端契约问题。
